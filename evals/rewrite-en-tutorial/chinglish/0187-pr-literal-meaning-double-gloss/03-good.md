In the last section you learned how to create a Branch and work on it in peace, without disturbing main. Isolation isn't the point of a branch, though. The point is that the work on it eventually flows back into the mainline. Finished work that just sits on a branch never becomes an official part of the project, and nobody else can use it. Merging is the step that fixes that: the changes you've verified on the branch get applied back to the main branch. On GitHub you start and finish that merge with a Pull Request (PR for short). The name is literal, a request to pull, and it reads like something you'd say out loud: I've finished some work, please merge it into the main branch.
