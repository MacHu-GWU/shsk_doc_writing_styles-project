This approach isn't limited to documentation experts. Say I wanted to automatically track the latest papers or news in some field every day and turn that into a daily digest. I'd use the same approach. First, I'd check whether the source publishes its own machine-readable index, something like `llms.txt`. Most serious sources do. Finding it isn't enough to trust it outright. I'd verify that it's a stable mechanism the source officially endorses. Only once I've confirmed that would I turn the discovery process into a Skill, one that fetches the latest entries fresh every time instead of me checking manually each day. After writing it, I'd test it against a few topics it has never seen, to confirm it pulls accurate results. It's the same skeleton I used to build the Claude Code expert, just pointed at a completely different domain, and it still works.
